“本节点”是当前进程，来源地址列显示它的监听或上游地址；下游节点每个 v4 会话一行，节点重连后会换一个新会话号。版本列来自节点连接时上报的软件版本，旧版本节点不提供该信息时显示“—”。下游的来源地址优先显示网关（雷池、nginx 等）转发的对端 IP，没有网关时显示直接连到本机的 TCP 地址。“IP 归属”在页面加载后由浏览器直接向公共 IP 归属接口查询来源 IP 的供应商和地理位置，不经过本服务；局域网、回环和无法识别的地址不查询，查询会把来源 IP 发送给该第三方服务。“管理服务”打开本节点或下游节点的服务列表，可在弹窗内增删改该节点自己的 [[proxies]]；“断开”只关闭当前会话，节点会按自己的重连间隔重新连上。“上级修改”列显示该节点是否允许它的上一跳修改本地服务：本节点可在顶部“上级修改”中切换，切换会重连上游会话；下游节点显示它自己上报的开关状态，只读时按钮变为“查看服务”。

本节点服务排在路由表前面，并优先于同名 v4 会话。“类型”区分本节点和下游节点；“来源”是各节点服务的配置来源，正常情况下都是 ht.toml，只有旧版本下游节点可能显示 HT_PROXIES。下游节点读取不到时显示“—”。下游路由的名称和目标地址从该节点的服务列表读取，读取不到时显示“—”或“下游转发”。“更新时间”是该路由行最近一次出现或发生变化的时间（域名、服务名、目标地址、x-auth，或下游会话与节点），未变化的行保持原时间；修改配置后可据此确认是否已经生效。新增、编辑或删除服务请在上方节点卡片的“管理服务”弹窗中操作。

接口列表

方法路径认证说明
GET/api/statusBearer进程状态：名称、传输、上游、连通性、服务数、下游节点数、活跃访客与本次运行的累计连接、上级修改开关及是否可编辑、热加载错误、版本、配置文件、运行时长
GET/api/settingsBearer本节点的全部配置项（含 Token 明文），[[proxies]] 除外
GET/api/settings/exportBearer下载磁盘上的 ht.toml（含注释和 Token 明文）
GET/api/proxiesBearer列出本地服务、x-auth 明文及来源；加 ?node= 或 ?session= 时列出该下游节点自己的服务
GET/api/routesBearer生效中的路由表，包含 v4 会话和每行的更新时间
GET/api/sessionsBearer已连接的下游节点：会话号、节点、版本、网关转发的来源 IP、TCP 对端、角色、连接时长、所属域名与是否可管理
PUT/api/settingsBearer替换本节点配置并写回 ht.toml；?dry_run=true 只检查是否需要重启，?restart=true 在需要时立即重建运行时。响应含 restart_required、restart_triggered、saved 和 settings
POST/api/restartBearer按磁盘上的 ht.toml 立即重建监听器和上游会话，进程本身不退出
PUT/api/proxies/{name}Bearer新增或替换服务，请求体 {"domain":"…","local_addr":"…","x-auth":"…"}；省略或 null 表示关闭访客认证。带 ?node=/?session= 时写入下游节点
POST/api/proxies/{name}/probeBearer从本节点拨号测试该服务的 local_addr，3 秒超时；返回 ok、latency_ms 和错误信息。仅支持本节点服务
PUT/api/settings/allow-upstream-modifyBearer只开关本节点是否允许上级修改本地服务，请求体 {"allowed":true}；保存后立即重连上游会话，无上游时返回 409
DELETE/api/proxies/{name}Bearer删除服务；带 ?node=/?session= 时删除下游节点的服务
DELETE/api/sessions/{id}Bearer断开一个下游会话；节点会按自己的重连间隔重新连上
GET/Basic本管理页面（唯一的 Basic 资源，其余接口统一用 Bearer）

所有 /api/* 使用 Authorization: Bearer <token>；页面本身使用 HTTP Basic，用户名 ht，密码为 token。错误响应为 {"error":"…","request_id":"…"}。下游参数 node 与 session 可同时给出，必须指向同一会话；不给出时只操作本进程。管理响应带 Cache-Control: no-store，但 x-auth 以明文返回，管理面必须通过 HTTPS 访问；同一控制面的节点需运行同一版本。

配置列表

键默认值说明
nameht进程名称，用于日志和 v4 节点标识
[server]无服务端模式开关；不写这个表就不监听任何端口，只作为客户端向上游拨出
[server].port7777唯一入口端口，访客、v4 会话和管理页/API 共用；0 为临时端口，仅在有 [upstream] 时允许
[server].bind127.0.0.1监听地址，必须是 IPv4/IPv6 字面量；Docker、局域网中继或直接公网访问时改成 0.0.0.0
[server].domain无入口 Host（原 control_host），启用管理页/API 和下游 v4 入口；省略时只监听访客路由。不能是泛域名，也不能与任何 [[proxies]] 域名重叠
[server].token无下游对等节点的共享 Token，同时是页面 Basic 密码；有 [upstream] 且省略时复用 [upstream].token
[server].keepalive_interval15服务端 WebSocket ping 间隔（秒），0 关闭保活
[server].max_pending_handshakes256同时等待 ClientHello 的已认证升级数上限
[server].max_sessions256同时接受的 v4 会话上限
[upstream].url无上一跳地址，ws:// 或 wss://，不带路径；省略即服务端入口
[upstream].token无上一跳的共享 Token，可与本机监听 token 不同
[upstream].allow_modifyfalse是否允许上一跳通过 v4 管理通道修改本节点的 [[proxies]]；关闭时上级仍可列出服务
[upstream].retry_interval1重连上一跳的间隔（秒）
[upstream].keepalive_interval15上游 WebSocket ping 间隔（秒），0 关闭保活
[[proxies]]空本节点直接服务的本地服务，字段为 name、domain、local_addr 和可选的 x-auth

所有配置项都来自 ht.toml，也可以在页面顶部“节点配置”或 PUT /api/settings 中修改；[server] 决定是否监听，[upstream] 决定是否向上游拨出，两个都有就是中继。当前生效的配置文件路径见顶部“配置文件”。
